## Security considerations

Browser clients have no table access until T011 policies are designed. Verification proposals/evidence are in private, separate from approved public fields. No global admin flag is read from user metadata. SECURITY INVOKER trigger functions have empty search paths and no client execute grants. A future privileged server/RPC operation must authorize each property action and use one transaction for initial owner assignment or ownership transfer. Neither constraints nor a service-role key validate applicant authority.

Phone/URL/location checks are structural and cannot establish business authenticity. Verification JSON cannot set owner/status fields but still needs semantic validation before approval. Public generated TypeScript types are not runtime input validation. Reviewer/owner deletion safeguards require intentional transfer, cleanup or anonymization workflows later. No retention promises, emails, paid resources or legal publication were introduced.
