# T018 — Public offer details

Discovery card titles link to `/offers/[slug]`. The server renders the approved offer price, pricing unit, comparison price and discount when present, guest and package coverage, inclusions, category details, terms, taxes, exclusions, restrictions and extra charges. The property section shows its address, verified status and directions when the recorded URL matches a supported Google Maps address.

Publication times use Sri Lanka time. Stay and redemption dates retain their stored calendar dates. The page displays the cover referenced by the approved revision. A labeled category illustration fills in when that reference has no matching processed asset.

## Files and migration

- `app/offers/[slug]/page.tsx` renders the detail page and its title and description metadata.
- `lib/offers/public-details.ts` loads the public detail projection with request-local memoization.
- `app/api/offers/[slug]/cover/route.ts` serves an eligible cover from private Storage.
- The discovery card, model and loader carry the offer slug. `app/globals.css` scopes the mobile filter clearance to pages that render the toolbar.
- `supabase/migrations/20261105081430_t018_public_offer_details.sql` adds the read functions and links the filtered feed. Generated database types reflect the RPC signatures.
- PostgreSQL tests cover approved snapshots, same-property covers and permissions. Browser tests cover navigation, dates, pricing, image loading, mobile fit, accessibility and missing offers.

The migration is applied to free development Supabase. The existing photo model supports one approved cover per revision, and that is what the detail page displays.

## Security and availability

The public projection checks current eligibility and returns only fields used by the page. It excludes private object paths, reviewer identifiers and provider contact fields. Nested objects in category details are omitted, and string arrays remain displayable.

The cover route accepts an offer slug and looks up the current approved cover with a server-only credential. The lookup requires the asset to belong to the offer property. It serves WebP bytes with `Cache-Control: no-store` and `nosniff`. Anonymous callers can read the approved detail projection. The direct path RPC requires the service role.

Unpublished, paused, expired and unknown slugs return 404 at this stage. T021 owns the visitor-facing unavailable-offer page. Upstream lookup failures show a temporary availability message. Development pages inherit the site's noindex policy.
