# T027 — Staff invitations and assignments

Owners can open Manage team from a property’s status or profile page. They create a link for a specific email address and share it with the invitee. After signing in with the verified address, the invitee opens the link and accepts access. Owners create a separate invitation for each property, so a single account can work across properties and each assignment can be removed independently.

A property has two staff slots. Each pending invitation reserves one slot for seven days. Owners can revoke pending invitations or remove active staff. Ownership changes revoke the former owner’s pending links. The team and acceptance controls require JavaScript.

## Files and migration

- `app/partner/properties/[id]/team/page.tsx` and `app/partner/invite/page.tsx` provide the owner and invitee pages. The property status and profile pages link to team management for owners.
- `components/partner/team-management.tsx` and `accept-staff-invite.tsx` render the invitation, acceptance and removal controls.
- `lib/partner/team-actions.ts` and `team.ts` define and submit the authenticated operations.
- `supabase/migrations/20261105154448_t027_staff_invitations.sql` is applied to free development Supabase. It adds the private invitation table, audited team operations and ownership-change revocation. It keeps the existing staff membership and slot constraints. `lib/database.types.ts` includes the generated function signatures.
- `tests/database/staff-invitations.test.mjs`, `tests/e2e/staff-invitations.spec.ts` and the partner fixture cover invitations and property-scoped access.

## Security

The database stores SHA-256 digests of randomly generated invitation tokens. The raw token is shared in the link fragment and reaches the server when the recipient submits acceptance. Owners see addresses only for their team and pending invitations. The database checks current ownership for management actions and checks the recipient’s verified email at acceptance. Property-level locking and unique staff slots prevent overbooking. Revoked, expired and consumed links cannot grant new access.

Removed staff lose membership-based access on subsequent requests. A photo URL signed before removal can still work until its existing short expiry. The app does not send invitation email. Recipients who need a new account still use the existing email confirmation flow.
