## Query and schema

No new table. One partial active-feed index supports descending first_published_at/UUID ordering. public.list_discovery_offers is an anonymous read-only SECURITY INVOKER wrapper for one fixed-search-path SECURITY DEFINER projection in the unexposed discovery_access schema. The public function returns bounded card JSON and continuation metadata. The existing private schema and raw offer/revision/table privileges are unchanged. The migration was generated by the CLI, replayed locally, applied only to free development, then aligned to its hosted version. Earlier migrations are untouched.

Default results are nationwide. Category and literal case-insensitive search across approved title/property/district/category are applied before ordering. Search input is bounded to 120 characters; percent/underscore are literal text, not SQL wildcard patterns. Query uses approved-revision fields and T009's current-time eligibility predicate: active offer, approved snapshot, verified/unarchived property, live publication window, unexpired Sri Lankan redemption date and current entitlement.

The feed starts newest first by first publication (UUID descending breaks timestamp ties). When the next card would be the third consecutive card from the same property, pick the newest available card from a different property and defer the displaced one. If no alternative remains, show the remaining matching cards instead of hiding them. This preserves freshness except for the necessary alternation. The query reads a bounded candidate batch using the existing three-active-offer cap and returns at most 12 cards.

Continuation carries the first-page publication cutoff, keyset frontier, previous property/run and a bounded list of displaced IDs. It is not an offset or a frozen availability snapshot. New first publications do not reorder an in-progress traversal; every page rechecks eligibility against database statement time. Paused, expired or otherwise unavailable deferred rows are omitted. An older offer that becomes newly eligible can appear only if its key is still within the remaining traversal. Already rendered cards are not polled; refresh rechecks their status. The cursor is URL-safe encoded, bounded and validated, not an authorization token. Forging it cannot bypass eligibility or the page cap.

## UI, security and accessibility

The first page renders on the server. Load More appends the next page, deduplicates IDs, guards simultaneous activation, keeps focus and existing cards on retry, and announces the added count. Without JavaScript it is a native continuation link. Search/category changes reset continuation. Initial error, empty and retry states are distinct. Read requests are uncached, use a bounded upstream timeout and only the Supabase publishable key. Provider error details are not returned to visitors.

The definer function is justified by intentional anonymous read access to a narrow projection; publishing raw private revisions or granting private schema access would disclose unrelated fields. The dedicated helper schema contains only the restricted read function and is not exposed through PostgREST. No user identity is needed for genuinely public data. No dynamic SQL, client-supplied availability time, raw cover path, contacts, reviewer IDs, moderation notes, subscriber data or draft fields appear in the projection. Query strings are parameterized and rendered as escaped React text. The cursor contains only ordering metadata for public results. Existing RLS/ACLs remain in force.

Cards show approved pricing/units, bounded inclusions and guest coverage, verified disclosure and local category illustrations. Private photo paths and draft media stay private. Detail links and reviewed public image delivery remain later tasks. Development noindex/nofollow remains. Sorting/filter UI, pagination beyond Load More refinements, offer details, analytics and SEO launch configuration are outside this task. No public rollout was performed.
