# T048 — Friday newsletter dispatch and campaign analytics

A saved newsletter can reserve a Friday send time in Sri Lanka. Scheduling checks the saved version, five or six approved live offers across categories, the weekly reservation, and the preceding edition’s selection. Reusing that entire selection is blocked. A scheduled draft is sealed and can be cancelled before dispatch starts.

The worker checks the edition and each subscriber before sending. At dispatch start it captures confirmed subscribers. New confirmations belong to a later edition. Withdrawal, suppression, or a fresh confirmation after that cutoff prevents the older queued delivery. A paused, expired, or changed selection stops the campaign. Empty audiences finish as failed.

Each recipient has one delivery and provider key. Retries preserve the message fingerprint and stop within the provider’s 24-hour key lifetime. The email includes a consent footer, a browser unsubscribe link, and one-click unsubscribe headers. Click links use opaque tokens and fixed Ayaale offer destinations.

The editor reports recipients, provider acceptance, delivery, failures, suppression, bounces, spam complaints, recorded link requests, and attributed unsubscribes. Click totals can include automated scanners. A hard bounce or spam complaint suppresses future marketing.

## Files and migration

- `supabase/migrations/20261107131726_t048_newsletter_dispatch.sql` adds scheduling, recipient claims, dispatch checks, private click links, campaign metrics, and unsubscribe attribution. It extends T043’s result recorder and signed delivery callback to support newsletter deliveries.
- `lib/newsletter/content.mjs` shares the T047 text and HTML template between preview and dispatch. `lib/newsletter/dispatch.mjs` builds the delivery links and provider payload.
- `scripts/run-newsletter-dispatch.mjs` runs a bounded dispatch batch. `app/newsletter/click/route.ts` resolves tracked links.
- `components/newsletter/campaign-status.tsx` and `lib/newsletter/schedule-actions.ts` provide scheduling and results in the existing editor.
- The newsletter dispatch database and unit tests cover timing, consent, retries, metric attribution, and message safety.

## Security

Only verified platform admins can schedule or read campaign metrics. The worker and click resolver use service-only database functions. Recipient addresses and raw tokens stay out of public responses and job logs. Subscriber locks serialize consent changes with dispatch preparation. Signed Resend callbacks update outcomes. Keep the link secret stable while email links and deliveries remain outstanding, and redact token query parameters from access logs.

## Commands and activation

```sh
AYAALE_TEST_DATABASE_URL=postgresql://postgres@127.0.0.1:54329/ayaale_test npm run check:all
node --env-file=.env.local scripts/run-newsletter-dispatch.mjs
git diff --check
```

Campaign delivery defaults to disabled. After verifying the sender, legal footer, privacy notice and delivery webhook, configure an authorized Render Node Cron Job with schedule `*/5 * * * *`, build command `npm ci`, and command `node scripts/run-newsletter-dispatch.mjs`. The database enforces Friday in Sri Lanka even though Render evaluates schedules in UTC. Set the Supabase URL and server secret, Resend sending key, sender address, HTTPS site origin, newsletter sender details and privacy URL, and a strong `NEWSLETTER_LINK_SECRET`. Then enable `NEWSLETTER_SEND_ENABLED` on the web and worker services. [Render Cron Jobs](https://render.com/docs/cronjobs)

The same Resend webhook used by T043 receives newsletter delivery events. Keep provider click and open tracking disabled. The application records only its own opaque link requests. [Resend idempotency keys](https://resend.com/docs/dashboard/emails/idempotency-keys)
