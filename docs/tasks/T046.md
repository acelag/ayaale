# T046 — Newsletter signup, confirmation, and unsubscribe

The homepage newsletter section asks for an email address and explicit consent to the Friday newsletter. A request creates a pending record. Confirmation requires a separate button press after following the emailed link. The 24-hour link records the exact consent text, consent version, privacy notice version, signup source, and confirmation time.

The confirmation email also contains an unsubscribe link, so people can withdraw before the first newsletter. The browser link opens a confirmation screen, and the mail-client endpoint accepts RFC 8058 one-click POST requests. Opening a link alone leaves the subscriber state unchanged. Rejoining requires a fresh request and confirmation. An unsubscribe link is scoped to the signup cycle it came from.

## Files and migration

- `app/page.tsx` and `components/newsletter` provide the homepage form and confirmation screens.
- `app/newsletter`, `app/api/newsletter/[action]/route.ts`, and `lib/newsletter` handle the browser and mail-client flows.
- `supabase/migrations/20261106191638_t046_newsletter_signup.sql` adds service-only subscriber operations and scopes unsubscribe tokens to their signup evidence. It reuses the existing private subscriber, consent, and token tables.
- `tests/database/newsletter-signup.test.mjs` and `tests/e2e/newsletter.spec.ts` cover consent state, expiry, rejoining, and browser and mail-client behavior.

## Security

The database stores token digests only. Browser links carry tokens in the URL fragment and the API receives them only on explicit submission. Sensitive responses are uncached and use no-referrer. Signup replies avoid revealing whether an address is subscribed. The API requires an explicit checkbox, limits request size, and applies global and hashed address budgets. The one-click endpoint accepts a token and the standard POST field without authentication or cookies. Exclude token query parameters from access logs and keep email click tracking off for confirmation links.

Signup defaults to closed. Before enabling it, configure a verified Resend sender, approved sender identity, address and contact text in `NEWSLETTER_SENDER_DETAILS`, and the published privacy notice URL and version. Set `RESEND_API_KEY`, `TRANSACTIONAL_EMAIL_FROM`, `NEWSLETTER_PRIVACY_URL`, and `NEWSLETTER_PRIVACY_VERSION` on the web service. Use a public HTTPS site origin. Enable `NEWSLETTER_SIGNUP_ENABLED` in a controlled deployment to verify a confirmation email in an authorized inbox before opening public signup. [Resend Send Email](https://resend.com/docs/api-reference/emails/send-email)

When a future newsletter includes one-click headers, point `List-Unsubscribe` at `/api/newsletter/unsubscribe?token=…` and use `List-Unsubscribe-Post: List-Unsubscribe=One-Click`. The token must be valid for that consent cycle. [RFC 8058](https://www.rfc-editor.org/rfc/rfc8058)
