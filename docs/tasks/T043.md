# T043 — Transactional email templates and delivery

Ayaale queues property verification notices for the current owner and offer review notices for the person who submitted the revision. The dispatcher uses the same private queue for existing complaint change requests and T042 reminders. It also provides templates for the future trial, performance, and urgent admin producers. Signup confirmation remains a Supabase Auth flow. The supplied confirmation template preserves the existing confirmation URL and browser flow.

The worker records one delivery per notification. A retry uses the same Resend idempotency key and the same request fingerprint. Temporary errors retry with increasing delays, up to five attempts and within 23 hours of the first claim. A rejected sender configuration stops the batch. The worker records provider acceptance separately from delivery. A signed callback can update the log to delivered, bounced, complained, failed, or suppressed. Late callbacks and duplicate events preserve terminal outcomes.

## Files and migration

- `supabase/migrations/20261106174050_t043_transactional_email.sql` adds queue producers, lease and request fingerprint fields, and service-only worker and delivery update functions on the existing notification and delivery tables.
- `lib/email`, `scripts/run-transactional-email.mjs`, and `app/api/webhooks/resend/route.ts` render email, send through Resend, and verify delivery callbacks.
- `supabase/templates/t043_confirm_signup.html` supplies copy for the existing Supabase Auth confirmation flow.
- `tests/database/transactional-email.test.mjs` and `scripts/transactional-email.test.mjs` cover queue ownership, retries, suppression, provider outcomes, and signed callbacks.

## Security

Email delivery requires explicit enablement. The worker rechecks recipient eligibility and current access before sending. It suppresses stale reminders and addresses with a recorded transactional bounce or spam complaint. Provider API credentials remain server-side. The webhook verifies the raw body signature and timestamp before processing a bounded payload. Logs store sanitized error codes and provider identifiers. Reviewer evidence and private complaint reports stay outside the templates.

## Commands and activation

```sh
AYAALE_TEST_DATABASE_URL=postgresql://postgres@127.0.0.1:54329/ayaale_test npm run check:all
node --env-file=.env.local scripts/run-transactional-email.mjs
git diff --check
```

For an authorized deployment, verify the sender domain in Resend. Configure the webhook for `email.sent`, `email.delivered`, `email.bounced`, `email.complained`, `email.failed` and `email.suppressed` at `/api/webhooks/resend`. Store `RESEND_WEBHOOK_SECRET` and `SUPABASE_SECRET_KEY` on the web service. [Resend webhook verification](https://resend.com/docs/webhooks/verify-webhooks-requests)

Run `node scripts/run-transactional-email.mjs` in a Node Cron Job every five minutes. The worker needs the HTTPS Supabase and site URLs, `SUPABASE_SECRET_KEY`, a Resend sending key in `RESEND_API_KEY`, and a verified sender in `TRANSACTIONAL_EMAIL_FROM`. Set `TRANSACTIONAL_EMAIL_ENABLED=true` when ready. Apply the optional signup copy through Supabase Auth email templates. Auth uses its own sender configuration. [Render Cron Jobs](https://render.com/docs/cronjobs)
