# T041 — Scheduled offer lifecycle

The lifecycle job expires offers after the publication deadline or the end of the redemption date in Sri Lanka. It activates approved or scheduled offers whose publication window is open when the verified property has a current entitlement and room under its Starter limit. It gives earlier publication times priority within a property. Paused offers can expire without being reactivated. Hidden, manually ended, and archived offers stay outside the job.

Public discovery, offer details, and property profiles already read fresh eligibility from Supabase on every request. An expired offer leaves public discovery at its cutoff even between job runs. A previously published URL still shows the ended page. The next request can see a newly activated offer as soon as its transaction commits. This provides fresh public pages without a separate cache purge or webhook.

## Files and migration

- `supabase/migrations/20261106171641_t041_offer_lifecycle.sql` adds the scheduler-only function and enables pg_cron where it is preloaded for the database. `lib/database.types.ts` records the new RPC.
- `supabase/operations/t041_development_schedule.sql` registers the once-per-minute job on free development.
- `scripts/run-offer-lifecycle.mjs` is the one-shot command for Render. `tests/database/offer-lifecycle.test.mjs` covers the transitions, historical URL, permissions and overlap.

## Security

Browser roles cannot run the job. The Render runner uses a server-only Supabase secret, sends it only to the configured HTTPS Supabase origin, and logs counts. The database job skips a concurrent invocation, locks properties before offers, and lets the existing capacity and audit triggers govern publication. Updates are transactional and bounded to 25 properties per run.
