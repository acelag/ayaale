Phase 6 starts with this task only. The integration is implemented with collection disabled by default. A GA4 property/stream and an approved published privacy notice are still required before activation. No Google account, live data stream, deployment settings or legal placeholders were changed. ## Files

- `components/analytics/privacy-analytics.tsx` implements optional consent controls and the Google tag loader, mounted in `app/layout.tsx`.
- `lib/analytics/privacy.mjs` and its declaration file define consent lifetime, public-page selection, safe event parameters, referrer origins and the campaign catalogue.
- Discovery search/category controls and offer contact controls carry fixed event labels. Public partner signup links use full document navigation so the Google runtime is unloaded before entering account pages.
- `app/newsletter/click/route.ts` appends the fixed newsletter UTM tags after resolving its opaque click token. The existing campaign click count remains separate.
- `.env.example` documents three public build-time settings. `playwright.config.ts`, `scripts/analytics-privacy.test.mjs`, `tests/e2e/analytics.spec.ts` and the newsletter editor browser test cover the integration.

No schema change, migration, package installation or paid service is required. Existing property analytics and newsletter consent are separate from optional GA consent.

## Events and campaign conventions

| Event               | Additional parameters                    | Meaning                                                     |
| ------------------- | ---------------------------------------- | ----------------------------------------------------------- |
| `page_view`         | `page_type`                              | A consenting visitor opens a public browsing page           |
| `offer_detail_view` | `page_type=offer`                        | Offer detail opened; not a unique visitor count             |
| `offer_search`      | none                                     | Search form submitted; no search text                       |
| `category_select`   | `category`: all, stays, dining, day_outs | Public category selected                                    |
| `contact_click`     | `channel`: call, whatsapp                | Contact control clicked; not a confirmed enquiry or booking |

All events include a generic page location/title and explicit destination. Paths are collapsed to `/`, `/offers` or `/properties`. Slugs, titles, property IDs, search text, phone numbers, emails, tokens, fragments and arbitrary query values are excluded from application-generated GA payloads. Referrers are empty except a small fixed set of search/social origins; their paths and queries are discarded. Google still receives connection and browser metadata when a visitor allows analytics.

Use lowercase catalogue tags; never put recipient details or tokens in UTM values. Generate links using `campaignQuery(name)`. A complete exact match is required for inbound attribution; unknown or duplicated UTM values are discarded. New campaigns require an intentional catalogue update.

| Catalogue name | utm_source | utm_medium | utm_campaign      |
| -------------- | ---------- | ---------- | ----------------- |
| newsletter     | newsletter | email      | weekly-newsletter |
| facebook       | facebook   | social     | social-launch     |
| instagram      | instagram  | social     | social-launch     |
| partner        | partner    | referral   | partner-launch    |

Example social URL: `https://ayaale.com/?utm_source=facebook&utm_medium=social&utm_campaign=social-launch`. Newsletter destinations automatically receive the newsletter tags after the service resolves the token; that token is never forwarded to GA.

## Privacy and security

Until allowed, no Google script or analytics request is created, including cookieless consent pings. Declining has no effect on browsing. Equal-style allow/decline controls and a persistent public-page “Privacy choices” button let visitors change their choice. The preference contains only a choice and timestamp, lasts 90 days, and falls back to memory if storage is unavailable. Do Not Track and Global Privacy Control override an allow choice. Expiry is checked at load, events and at least once per minute in an active tab.

Ads storage, ad user data and ad personalization stay denied; Google Signals and ad personalization are disabled in code. Analytics cookies use the current host and a 90-day non-renewing lifetime. Revocation disables the stream, clears its host cookies and reloads to remove the vendor runtime. Cross-tab preference changes also stop collection. Requests already sent cannot be withdrawn. Private, authentication, admin, API and newsletter token pages never initialize the tag. Entering an account from a public page replaces the document. No user ID, enhanced conversions, advertising link identifiers or user-provided data are added.

The vendor runtime is tested with intercepted requests, not live Google processing. Do not enable a second Google tag or Tag Manager container. Disable the stream's automatic Enhanced Measurement before activation: otherwise automatic searches, outbound links, forms or browser history events can defeat application sanitization. [Google Enhanced Measurement](https://support.google.com/analytics/answer/9216061?hl=en), [manual pageviews](https://developers.google.com/analytics/devguides/collection/ga4/views), [consent implementation](https://developers.google.com/tag-platform/security/guides/consent), [privacy controls](https://developers.google.com/tag-platform/security/guides/privacy).

## Activation and reporting

1. Create or select a dedicated GA4 web stream for the intended environment. Keep development on free infrastructure; production activation is a separate decision. Do not enable cross-domain linking, Google Signals, ads integrations, user-provided data or additional destinations. Turn off all Enhanced Measurement, including browser-history pageviews, site search, outbound clicks and forms. Set the shortest appropriate event retention (initial recommendation: two months), disable retention reset and restrict account access.
2. Approve and publish the privacy notice with actual operator/contact/processor details and a description of Google processing, the 90-day choice/cookies, withdrawal and international transfers. The current legal drafts remain unpublished with placeholders.
3. Set `NEXT_PUBLIC_GA4_MEASUREMENT_ID=G-…`, `NEXT_PUBLIC_ANALYTICS_PRIVACY_URL=https://…` and `NEXT_PUBLIC_ANALYTICS_ENABLED=true`, then rebuild. These settings are public; never place API secrets in them. Missing or invalid settings keep collection off. Disable with `NEXT_PUBLIC_ANALYTICS_ENABLED=false` and rebuild.
4. With an authorized test browser, inspect network requests and GA Realtime for one sanitized pageview, an offer detail view and a contact click. Confirm no raw URL/title/contact data appears in actual vendor requests. Decline and confirm no Google traffic, then allow/revoke and confirm collection stops. This live check is still pending.
5. Use GA traffic acquisition by session source/medium/campaign and event counts for aggregate trends. Register event-scoped `page_type`, `channel` and `category` custom dimensions if needed. A contact click is an engagement indicator, not revenue. Reporting covers consenting visitors only and is affected by blockers, shared devices and missing/stripped campaigns; don't infer exact totals or combine it with subscriber identities. T051 will separately address source reporting inside Ayaale.
