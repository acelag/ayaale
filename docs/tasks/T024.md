# T024 — Partner signup and property registration

The homepage’s List Your Property link opens partner signup. After email confirmation, a partner can sign in, register a property, and check its verification status. Registration asks for a property name, category, type, street address, district, private contact name, and a business phone or WhatsApp number. The Google Maps link and website are optional at intake. Photos can be added privately from the status screen after submission.

## Files and migration

- `app/partner/` contains signup, sign-in, registration, and owner-only status pages. `components/partner/` contains the forms and photo upload control.
- `lib/partner/` validates registration, checks the session, and routes the partner through the flow. The homepage and discovery header link to signup.
- `lib/auth/actions.ts`, `lib/supabase/server.ts`, and `app/auth/callback/route.ts` reuse the existing authentication, email confirmation, and abuse controls.
- `supabase/migrations/20261105150309_t024_partner_registration.sql` adds an authenticated registration function, private applicant contact name, and submission limits. It uses the existing property, membership, verification request and audit tables. The migration is applied to free development Supabase, and `lib/database.types.ts` reflects it.
- `tests/database/partner-registration.test.mjs` and `tests/e2e/partner-registration.spec.ts` cover registration and the browser flow. The browser uses a loopback Auth and Storage fixture.

## Security and workflow

Registration uses the verified caller’s identity. One transaction creates the pending property, owner membership and initial review request. Retrying the same submission ID returns the original registration. A pending property is excluded from public discovery and receives no trial until approval. The review contact’s name is excluded from public projections. The owner’s status reads use RLS. Photo uploads reuse the existing protected route and private Storage.

New submissions are limited to five per account and 100 overall per hourly window. Signup keeps the existing rate limits and honeypot. Confirmation exchanges the email code using the signup browser’s PKCE verifier. If the email was confirmed in another browser, the partner can sign in with their password. The callback only redirects within the configured site origin. The forms require JavaScript in the current build.
