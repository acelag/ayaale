# T035 — Property verification

From the admin overview, open **Verification queue**. The queues show pending reviews, properties waiting for information, verified properties, and rejected or suspended properties. Open a property to inspect the application, proposed changes, private photo previews, and recent decisions.

Approval requires the reviewer to confirm business existence and applicant authority, record the verification method and evidence, and confirm a Google Maps link and coordinates. Approval applies the reviewed profile and any proposed gallery in one transaction. First approval uses the existing Starter trial allocation rules. Requesting information gives the owner a message and lets them resubmit the same application. Rejecting a proposed change leaves the approved profile available. Suspension hides the public property and its offers through the existing eligibility checks.

## Files and migration

- `app/admin/verifications/page.tsx`, `app/admin/verifications/[id]/page.tsx`, and `app/admin/page.tsx` provide queue navigation, application review, and decision history.
- `components/admin/verification-form.tsx` and `lib/admin/verification*.ts` implement the checklist, decision form, and typed server action.
- `app/api/properties/[propertyId]/photos/[photoId]/route.ts` permits verified platform administrators to request the existing short-lived private photo previews.
- `app/partner/properties/[id]/profile/page.tsx` and `lib/partner/profile-editor.ts` show the partner message and support the request-for-information round trip.
- `supabase/migrations/20261106093528_t035_property_verification.sql` adds an append-only verification decision history and admin queue and decision functions. It updates the owner profile functions to permit resubmission and exposes the new API signatures through `lib/database.types.ts`.
- `tests/database/property-editor.test.mjs`, `tests/e2e/property-verification.spec.ts`, and the browser fixture cover the review workflow.

## Security

Decision writes require a verified platform administrator and lock the property and review before comparing the displayed version. Decisions, profile changes, and gallery assignments commit together. Database constraints reject out-of-range coordinates and photos from another property. Evidence and reviewer history stay in the private admin projection. The partner profile only receives the partner-facing message. Suspension requires explicit confirmation and a reason.
