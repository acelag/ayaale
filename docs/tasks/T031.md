# T031 — Per-property analytics

From a property’s status page, open **Property analytics** to see offer detail views, WhatsApp clicks, Call clicks and contact click rate. The cards, daily chart and offer table use the selected 7-, 30- or 90-day range, including today in Sri Lanka time. Monthly comparison shows the current month to date beside the full previous month. The daily chart has a keyboard-accessible table with the same values. Previously published offers remain in the report after they end.

Contact click rate is total WhatsApp and Call clicks divided by recorded offer detail views. It can exceed 100% because a view can lead to multiple clicks. A dash means the denominator is zero. Clicks measure contact button use.

## Files and migration

- `app/partner/properties/[id]/analytics/page.tsx` and `components/partner/property-analytics.tsx` render the dashboard, time range links and paginated offer table.
- `app/partner/properties/[id]/page.tsx`, `app/partner/page.tsx` and `components/partner/property-switcher.tsx` link to the dashboard and keep the property switcher in analytics.
- `app/offers/[slug]/page.tsx`, `components/offers/record-offer-view.tsx`, `app/api/offers/[slug]/view/route.ts` and `lib/offers/view-tracking.ts` collect views on visible, active offer detail pages. `.env.example` documents the environment setting.
- `supabase/migrations/20261106044502_t031_property_analytics.sql` adds the scoped analytics query and the server-only view recorder, and extends the existing rate limiter. It reuses the private view and click event tables and their time indexes. No table changes or historical backfill are needed. `lib/database.types.ts` contains the Supabase signatures.
- `tests/database/partner-overview.test.mjs`, `tests/e2e/property-analytics.spec.ts` and the browser test fixtures cover the reporting and collection paths.

## Security and collection

The database verifies current owner or staff membership and returns property-scoped aggregate counts. Raw events and deduplication keys stay private. Aggregation excludes flagged events and future timestamps. The view endpoint checks the request origin and current offer availability. It filters common bot and synthetic user agents, honors supported privacy signals, and applies global and per-offer request limits.

For 30 minutes, repeat views of the same offer in a browser tab reuse a random token. The database stores a hash of the token. The view payload carries no customer identity, raw IP address, referrer or contact details. Counts represent recorded activity. Browser privacy settings, blocked scripts and separate tabs can affect measurement.

Collection defaults to on in development. Set `OFFER_VIEW_TRACKING=off` for internal test sessions against a real database. Other environments require explicit `OFFER_VIEW_TRACKING=on` after the applicable privacy review and notices. Previously recorded counts remain visible while collection is off.

## Acceptance and verification

- Open Property analytics as an owner or assigned staff member. Change the date range and check the cards, daily data, offer rows and monthly comparison.
- Switch properties and confirm that another property's activity appears only with an assignment.
- Reload an active public offer within 30 minutes in the same tab and confirm that the view token is reused. Verify that paused offers and cross-origin requests cannot create a view.
- Verify a previous month's event at the Sri Lanka calendar boundary, excluded events, and historical reporting after an offer ends.
