## Commands

Use the pinned Node 24 runtime and a disposable loopback PostgreSQL cluster with the `ayaale_test` base database.

```sh
# Focused new cases plus existing dispatch regression
AYAALE_TEST_DATABASE_URL=postgresql://postgres@127.0.0.1:54329/ayaale_test node --test tests/database/negative-cases.test.mjs tests/database/newsletter-dispatch.test.mjs

# Full verification
AYAALE_TEST_DATABASE_URL=postgresql://postgres@127.0.0.1:54329/ayaale_test npm run test:db
npm run check
npm run test:e2e
git diff --check
```

The existing helper accepts only loopback `/ayaale_test`, rejects hosted endpoints/query/fragment overrides, and creates/drops its own random database. Browser regression uses local synthetic API/Auth fixtures on port 3101 and a production Next.js build on port 3100. Run build-backed suites sequentially because they share `.next` and ports.

## Results and interpretation

- Full database suite: **181 passed**, including **9 new negative regressions**.
- Formatting, ESLint and TypeScript: passed.
- Unit and design contrast checks: **36 unit cases and 20 contrast pairs passed**.
- Full desktop/mobile Chromium browser regression: **141 passed, one existing desktop-only skip**.
- Diff validation: passed. Disposable database cleanup was checked and the dedicated test cluster stopped afterward.

The first focused run passed eleven cases and found one incorrect expectation in the new subscription test: T021 intentionally returns `unavailable` when entitlement is missing, reserving `ended` for elapsed offer dates or ended/expired status. The new test was aligned with that documented contract and strengthened to assert that the full `offer` payload is absent while raw stored statuses are still active. The public eligibility requirement was not weakened or changed.

Browser coverage rechecks access denial for owners/staff on admin routes, foreign-property/subscription screens, registration confirmation, invalid/expired confirmation links, duplicate ownership claims, offer review prerequisites and report-form validation/retry behavior. Business-state assertions use real PostgreSQL separately; mocked browser APIs do not prove hosted Supabase/Auth correctness. The T053 database-backed full journey remains available through `npm run test:journey` and was not changed in T054.

## Security and scope

Tests use real PostgreSQL roles/RLS and business functions. Only synthetic time fixtures use privileged timestamp adjustments with triggers temporarily bypassed inside a rollback-only local transaction, then restored before invoking the tested function. Product functions still evaluate current entitlement and dispatch eligibility; no production bypass, grant, table policy or application test endpoint was introduced.

Newsletter tests stop at preparation: no provider is called and no campaign is sent. Contact ingestion is checked without calling a telephone/WhatsApp destination. Report strings are deliberate synthetic allegations; they are not a mechanism for automatically judging real reports. Owner/subscriber/reporter data access remains covered by the existing authorization suite.

This is repeatable local regression evidence, not a live-provider penetration test, proof of real email delivery or signoff of an undeployed candidate. No paid resources, billing settings, indexing or live traffic collection were changed.
