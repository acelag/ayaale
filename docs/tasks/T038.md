# T038 — Complaint moderation

Open **Complaint moderation** from the admin overview. The unresolved queue shows business and offer complaints, highest priority first and oldest first within each priority. Closed complaints are separate. Each case shows its report, moderation decisions, and other complaints for the same business, including complaints about its offers. The queue lists the internal review targets from the build plan.

Admins can change priority, start an investigation, request changes, hide or restore the listing, resolve the complaint, or dismiss it. Each action requires an internal note. Hiding an offer withdraws only that offer; hiding a business suspends its profile and public offers. Restoring a listing requires an unresolved case that recorded the current hide, and offer publication rules still apply. Closing a case preserves the current visibility. Existing complaint intake remains manual: report count has no automatic effect on visibility.

A request for changes records separate owner instructions in the existing notification queue. T038 does not add an inbox or send email; delivery and the notification bell are covered by T043 and T045.

## Files and migration

- `app/admin/reports`, `app/admin/page.tsx`, and `components/admin/report-*.tsx` add the queue, detail and history pages, accessible form, and overview entry.
- `lib/admin/report-actions.ts`, `lib/admin/reports.ts`, and `lib/database.types.ts` handle actions, feedback, and API types.
- `supabase/migrations/20261106162306_t038_report_moderation.sql` adds the guarded read and mutation functions, two queue indexes, and before/after changes to the existing append-only moderation ledger. No new tables or secrets are required.
- `tests/database/report-moderation.test.mjs`, `tests/e2e/report-moderation.spec.ts`, and the browser fixture cover the workflow and permissions.

## Security

Verified platform administrator membership is checked in the database for every read and write. Anonymous callers cannot execute these functions. Signed-in owners and staff cannot read raw reports or moderate them. A stale report version cannot overwrite a newer decision. Report state, listing state, notification events, and audit records are written together where applicable. Private visitor comments, reporter emails, and internal notes stay out of queue summaries, public pages, and owner notifications. Admin pages inherit the noindex policy.
