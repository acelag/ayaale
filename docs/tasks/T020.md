# T020 — Public property profiles

Offer details link to `/properties/[slug]`. A verified property has a public profile even when it has zero active offers or its subscription has ended. The page shows the property description, address, category, verified badge, directions and available public contact, website, social and Google reviews links.

The first four listed amenities appear immediately. View all amenities expands the rest. Amenities describe the property, while offer inclusions describe a package. The first assigned public photo becomes the cover and subsequent photos form the gallery. Profiles without an assigned cover show a labeled category illustration.

## Files and migration

- `app/properties/[slug]/page.tsx` renders the profile and its metadata.
- `lib/properties/public-profile.ts` loads the public projection. `lib/properties/public-links.ts` validates outbound links and shares Google Maps validation with offer details.
- `app/api/public-properties/[slug]/photos/[position]/route.ts` serves photos assigned to the public profile.
- `app/offers/[slug]/page.tsx` and `lib/offers/public-details.ts` use the property slug from the approved offer projection.
- `supabase/migrations/20261105085736_t020_public_property_profiles.sql` adds bounded amenity and link fields, ordered public photo assignments, profile and photo RPCs, and the property slug on offer details. It is applied to free development Supabase.
- Generated public database types, database tests and browser fixtures cover the new contract.

## Security and availability

The public projection accepts only verified, unarchived properties and includes current offer links using the existing offer eligibility check. Suspended and unknown profiles return 404. Anonymous callers receive the public projection through a read-only RPC. Raw property rows and Storage paths require their existing privileged access.

Photo assignments require a processed asset from the same property and alt text. The photo route accepts a slug and a position from 1 to 12, checks eligibility on each request and serves WebP with `no-store` and `nosniff`. The Storage path lookup requires the service role. The migration keeps profile photo assignment writes service-only and audited.

The review control links to a configured Google destination. Development metadata inherits the site's noindex policy.
