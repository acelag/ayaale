# T051 — Traffic-source summaries

Implemented for property analytics and admin platform analytics. This task adds bounded, consent-aware attribution to recorded offer detail views and shows source counts plus percentages for the selected 7/30/90-day Sri Lanka date range. Missing, unsupported or ambiguous evidence remains **Unknown**. An absent referrer is never inferred to mean Direct.

The migration is installed on the existing free development Supabase project `buntpenbggavsoskhfnu`. Application changes are local and have not been published or deployed to Render. The live collection/GA flags remain disabled. No paid resource, Google activation, email activation, indexing change or T052 work is included.

## Schema and migration

No tables, event columns, identities or tracking cookies are added. The existing private `source` and `source_reliable` columns are reused.

- `private.get_property_analytics(uuid,integer,integer)` now returns `sources`, grouped over the selected trend range, scoped through existing verified owner/staff authorization. Excluded/future events and unpublished offers remain outside the counts. Admin reporting already groups these same private view sources.
- New `public.record_offer_view_attributed(text,uuid,text)` is security invoker with an empty search path, callable only by `service_role`. It preserves live-offer eligibility, request budgets and deduplication. Unknown inputs normalize to Unknown; a retry cannot change the first recorded source.
- Original `public.record_offer_view(text,uuid)` remains available to older deployments and records Unknown through the same implementation. No historical events are reclassified.
- Existing RLS, reporting grants and administrator checks are preserved. No raw event access is added for partners.

The migration was created using the installed Supabase CLI, tested by applying all migrations to isolated local databases, then applied through the Supabase migration tool to the free development project. Hosted checks confirm anonymous/authenticated callers cannot execute the new ingestion RPC, the service role can, the property function includes sources, and an unassigned property returns null.

## Attribution rules and limits

- Attribution requires the existing valid analytics configuration and a current Allow analytics preference. DNT/GPC and the existing view-collection switch remain effective. Disabled/missing settings, missing/expired/declined consent and blocked consent storage yield Unknown. Basic view collection retains its separate existing configuration.
- Only the complete exact T049 catalogue campaigns are accepted: newsletter/email/weekly-newsletter; facebook or instagram/social/social-launch; partner/referral/partner-launch. Partial, duplicated, extra, case-changed or unknown UTM tags yield Unknown even if a plausible referrer exists.
- Recognized HTTPS referrer hosts classify Google/Bing as Search and the fixed Facebook/Instagram/t.co origins as Social. Credentials, non-default ports, lookalike hosts and arbitrary referral hosts are rejected. Paths/queries are never transmitted or persisted.
- A consenting public landing source can carry across client navigation within the same document for up to 30 minutes. It is held only in memory as a category, origin and timestamps, with no visitor identifier or raw URL/query. Repeated evidence does not renew the window. Full reloads/new tabs start afresh; private navigation, withdrawal and invalid consent clear it. No cross-session or cross-device attribution is inferred.
- The view request omits credentials and referrer and carries only a fixed category plus the pre-existing random deduplication token. The server validates categories and configuration; browser evidence is still client-supplied and can be forged. These figures are indicative, never a billing, entitlement or verified-conversion signal.
- Counts represent recorded offer views, not site sessions, people, enquiries or bookings. Percentages use all recorded views including Unknown as their denominator. GA covers a different consented event population and may disagree. Direct is retained as a label for pre-existing reliable records but is never manufactured by this collector.
- Existing historical Unknown records stay Unknown. No real traffic event or test email was created in the hosted database during verification.
