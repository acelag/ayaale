## Schema / migration

public.offers stores stable identity/status and an approved-revision pointer. private.offer_revisions stores bounded pricing/coverage/category/date/terms/photo-reference snapshots, with content sealed on submission. private.offer_status_history stores append-only parent status/pointer changes. Checks, foreign keys, indexes, generated discount, timestamps, RLS and least-privilege ACLs protect the new tables. Details and limitations are in the [offer schema guide](../database/T008_OFFERS.md).

## Security considerations

RLS enabled and browser privileges absent on all three tables; revisions and history are in the unexposed private schema. No public policy or RPC is opened early. Inherited service-role DELETE/history-UPDATE privileges are explicitly removed. SECURITY INVOKER triggers use fixed empty search paths; no browser EXECUTE grant. Stable URL/property identity and same-offer revision/history foreign keys prevent cross-offer references. Submitted snapshots and completed decisions are immutable; pending edits cannot replace approved public content.

Service roles still require trusted server-side authorization in T011; reviewer IDs do not prove admin status by themselves. Cover paths do not prove file ownership/existence. Category JSON needs semantic validation in T028. Activation checks do not replace query-time validity, subscription/cap enforcement or automatic expiry jobs. Hard deletion/retention cleanup needs a reviewed maintenance plan. No customer identifiers, provider messages, payments, file uploads or legal publication were introduced.
