# T022 — Public issue reporting

Visitors can report an issue on a public offer or property page without signing in. The form requires a reason and accepts an optional comment and email for follow-up. Previously published offers with a public title remain reportable after they pause or end. Withdrawn pages omit the form. Submitting a report requires JavaScript in the current Next.js build.

## Files and migration

- `app/offers/[slug]/page.tsx` and `app/properties/[slug]/page.tsx` link to and render the report form.
- `components/reports/issue-report-form.tsx` renders the shared form, field labels, errors and submission confirmation.
- `lib/reports/actions.ts` validates the form and sends the submission through a server-only client. `lib/reports/form.ts` defines shared reasons and form state.
- `supabase/migrations/20261105104217_t022_public_issue_reports.sql` adds a service-only intake function and extends the existing request budgets. It is applied to free development Supabase. The intake uses the existing private report table, admin read policy and audit trigger.
- `lib/database.types.ts` records the generated RPC signature.
- `tests/database/issue-reports.test.mjs`, `tests/e2e/issue-report.spec.ts` and the browser fixtures cover report intake and visitor behavior.

## Security and review

The server checks the request origin and validates the target, reason, comment and email. The database resolves the target and verifies that it is public. The server keeps the credential private and the database restricts direct intake calls to the service role. Reporter emails and comments are restricted to authorized Ayaale reviewers.

The form includes a honeypot, an idempotent submission ID, and database-backed limits of 20 reports per target and 200 overall per hourly window. Accepted reports enter the existing queue as open with medium priority for manual review. Submission does not change offer or property visibility.
